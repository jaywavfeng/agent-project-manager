# v1.1.0 validation and evidence boundaries

Baseline: v1.0.0 commit `88c05ae`. The 117 tests at that commit passed before changes.

v1.1.0 is a structural-cost release. It removes duplicated state rather than adding capability, under the governing rule: **the manager must cost less than the work it saves.**

## What changed

**A standalone project is three files.** `init` now creates exactly `STATE.json`, `memory.jsonl` and `PROJECT_STATUS.md`. `PLAN.md`, `workers/`, `review/` and `inbox/owner/` are created by the command that first needs them. Validation is layered: a file or directory is required only when the loaded state says the feature is in use, so a minimal project validates cleanly and an older runtime still validates.

**`HANDOFF.md` is gone.** It duplicated `STATE.json`, `memory.jsonl` and `PLAN.md`, and a hand-written summary is precisely the state that drifts out of sync. `context --role lead` now renders the takeover briefing on demand from those canonical files. A legacy `HANDOFF.md` is still read if a pre-v1.1 project has one, so no existing runtime breaks.

**Long-lived intent and constraints are never archived.** `memory-consolidate` previously truncated the active file by order alone, ignoring `kind`. Because `read_entries` only reads `memory.jsonl`, an archived `human-intent` or `constraint` became permanently invisible to `relevant()` — a silent loss of a user requirement. `human-intent` and `constraint` are now exempt from the retention window, and the command reports how many entries it protected.

## Measured overhead reduction

Both figures are produced by running `init` on an empty directory with an identical command, then counting files and summing UTF-8 bytes under `.agent-project-manager/`. The baseline uses a clean worktree at `88c05ae`.

| | v1.0.0 | v1.1.0 | Change |
|---|---|---|---|
| Files created by `init` | 10 | 3 | **-70%** |
| Total bytes created | 3,283 | 870 | **-73%** |

The ten v1.0.0 files were `HANDOFF.md`, `OWNER_DIRECTIVES.md`, `OWNER_STATUS.md`, `PLAN.md`, `PROJECT_STATUS.md`, `STATE.json`, `memory.jsonl` and three `review/` files. `PLAN.md` and the review files were pre-seeded with templates that a standalone project may never fill in, so the old default paid for scaffolding it did not use.

## Behavioral verification

Local regression: all 119 tests pass (117 baseline plus 2 new memory-protection cases). The suite includes the v1.1.0 behavior cases:

- `init` creates exactly the three minimal files and nothing else.
- A minimal project passes `validate`; the review, worker and completion-archive checks are conditional on the state actually requiring them.
- `context --role lead` synthesizes a briefing containing the final goal and next action with no `HANDOFF.md` on disk.
- `memory-consolidate --keep 1` over 30+ newer entries still keeps every `human-intent` and `constraint` entry, and those entries still surface through `memory-show --task` for an unrelated task.
- Completion archival records only the files that exist, and reopening still validates.

Commands:

```console
python -m unittest discover -s tests -v
```

CI covers Windows/Ubuntu x Python 3.9/3.13.

## Limits

The file and byte counts are exact for `init`. They are not a measured token or billing saving: real coordination-token ratio and billed usage remain **unmeasured / Benchmark pending**. Fewer files reduce the scaffolding an agent must read and keep consistent, but no live model run was instrumented to attribute tokens to it.

The synthesized briefing is derived from state, memory and the plan. It therefore cannot contain context that was never recorded — a project that relied on free-form prose in `HANDOFF.md` outside the canonical files loses that prose unless it was also written to memory. This is intentional: unrecorded context was already the least reliable part of the old packet.

Legacy `HANDOFF.md` read support is retained for compatibility and is not exercised by new runtimes.
