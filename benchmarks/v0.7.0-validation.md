# v0.7.0 validation and evidence boundaries

Baseline: v0.6.0 commit `204002a817866d3ba652ab790ecb103ae538fb63`. The original 71 tests passed before changes. Additional isolated probes exposed completed-dependency reuse, inactive-role reuse, blocked-review repair and missing review-verdict gating defects.

## Behavioral verification

Local regression: all 94 tests passed, including 23 v0.7.0 behavior cases. Skill validation and all 28 CLI help paths passed; all Python sources passed Python 3.9 grammar parsing.

The regression suite adds direct Lead execution, safe takeover and stale-executor rejection, truthful stopped-assignment archives, dependency reuse, interrupted controls, review cancellation/verdicts, independent-thread routing, bidirectional durable receipts, combined result callbacks, bounded context, artifact preview/quarantine/restore/retention, current references, Git-tracked content, changed directories, move/restore interruptions, symlink/junction rejection and completed-project immutability.

Commands:

```console
python -m unittest discover -s tests -v
python benchmarks/measure_v070.py
```

Release checks also include skill validation, every statectl/benchmark CLI help path, Python 3.9 grammar compatibility, archive/install smoke testing, `git diff --check`, and Windows/Ubuntu x Python 3.9/3.13 CI. CI runs are attached to the published commit; final run outcomes are reported in the release delivery.

## Reproducible proxies

[Static/context measurements](v0.7.0-static-context.json) are generated from the baseline Git archive and current code. Their fixtures are synthetic. Executable/project paths are normalized, and metrics are serialized UTF-8 bytes and Python whitespace word counts, not model tokens.

- Entrypoint: 1,157 -> 790 words (31.7% less).
- Core entrypoint plus coordination/state/dispatch/profile references: 3,923 -> 2,664 words (32.1% less).
- Housekeeping adds a conditional 670-word reference. Loading it too gives 3,334 words, still below the old 3,923-word corresponding core set. Ordinary continuation does not reload this set.
- One active Worker and no terminal Workers: context grows from 1,827 to 2,036 bytes because explicit pagination/executor/housekeeping fields are added.
- The same active work plus 100 terminal Worker records: baseline context is 301,421 bytes; v0.7.0 is 2,038 bytes. The new output grows only by the terminal-count digits, not historical verification text.
- Documented send/return success path: 7 -> 6 tool calls when using the combined callback result write. This excludes shared initialization, assignment, binding and host-observation work. It is a protocol-step comparison, not a measured live conversation.

## Limits

Real coordination-token ratio and billing savings remain **unmeasured / Benchmark pending**. No live independent-conversation creation or bidirectional desktop messaging was available in the implementation session. Host receipts in tests are synthetic, not proof of actual routing or billing. No automatic subagent route was used. Scenario definitions are not independent Agent-run evidence.

Housekeeping relies on truthful explicit release declarations for external processes/consumers; the helper cannot infer every semantic dependency or provide an OS sandbox against a malicious concurrent writer. Unknown content, current references, protected artifacts and unsafe trees are retained. Metadata inventories are used only for registered cleanup candidates, not a project-wide checksum system. Existing historical task evidence has no automatic expiration.
